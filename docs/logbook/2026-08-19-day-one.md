# 2026-08-19 — Day one: building the dojo

**Kata:** none — setup session
**Verdict:** pass
**Elapsed:** one session

This is a setup entry, not a training entry. It exists so the logbook starts at the same
moment the repository does. The first real entry is due after kata 001, and it will have a
"what failed" section with content in it.

## What I set out to do

Stand up a public repository where practice with AI agents accumulates as versioned artifacts
instead of evaporating with the session. Starting with Claude Code, not ending there.

## What failed

Nothing broke, but two things in the initial design were wrong and had to be corrected before
the first commit. Recording them because they are the kind of thing that would have cost real
time later.

**`.claude/` was going to live under `code/`.** The macro architecture is `code/`, `docs/`,
`README.md`, `.gitignore`, deliberately generic and consistent across my repositories, so the
instinct was to push everything down into it. That does not work: Claude Code discovers
project configuration at the repository root, and configuration anywhere else silently does
not load. Silently is the problem — it would have looked like the hook was written wrong
rather than placed wrong.

The resolution was not an exception to the rule but a better statement of it: the invariant is
**infrastructure at the root, content in `code/` and `docs/`**. `.gitignore` configures git,
`.claude/` configures the agent, both are infrastructure. Written up as
[ADR-0002](../adr/0002-repository-macro-architecture.md).

**Containers were on the day-one list.** They were going to be scaffolding built before there
was anything to put in it. Cut, and deferred to phase 4, where an isolated blast radius is
what makes unattended runs sensible rather than reckless. Building the dojo is not training
in it; that distinction is the main thing this repository has to defend against.

## What worked instead

Two rules written into the README as constraints rather than aspirations, because both
failures above are instances of the same drift:

1. Nothing enters the repo unless it produces an artifact that runs or applies.
2. Every kata carries its own pass criteria.

And one decision that follows from taking rule 1 seriously on day one: the secret-blocking
hook is real and working rather than planned. The repository is public, so the boundary
against committing credentials cannot depend on remembering the boundary. That is the
difference between `CLAUDE.md` and a hook — advice versus guarantee — and it was worth
spending the first phase-3 artifact on.

## What I would tell someone else

The structure is not the work. I spent this session building a place to practice, and that
produced exactly zero repetitions. It was worth it once. It will not be worth it twice.
